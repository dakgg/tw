# 2026-10-30 · EH 숙박 운영 워크스페이스 전환

## 구현

- 기존 여행 수요·지도·주변 시세·공휴일·환율 기능과 API를 제거하고 숙박 운영 워크스페이스로 교체했다. 이전 조사 문서는 `docs/archive/`에 보존했다.
- 사용자 요청에 따라 가제 Project EH로 전환한 뒤 최종 표시명을 **EH**로 확정했다. Zest는 타 업체의 제품명으로 참고자료 출처에만 사용한다.
- 예약·객실 달력, 요금·재고, 청소 일정, 객실 이슈, 게스트 노트, 매출·정산, 메시지 초안, 보상 증빙, 숙소·객실 설정을 구현했다.
- 첫 화면에 로그인·가입을 추가했다. 서버의 ID/PW 검증, scrypt 비밀번호 해시, HttpOnly 세션 쿠키, 로그아웃, 비밀번호 변경, 요청 출처 및 시도 횟수 제한을 적용했다.
- 사용자마다 숙소·예약·OTA 설정을 별도 파일에 저장한다. 인증된 계정으로만 저장소를 선택하고 타 계정 리소스 접근 및 다른 탭의 계정 변경 후 오래된 요청을 차단한다.

## 출처와 데이터

- Zest 공식 홈페이지와 사용자가 제공한 `zest-console-intro.pdf`를 기능 참고자료로 사용했다. 문서 내용은 구현 지시로 취급하지 않았다.
- 예시 숙소·게스트·예약은 가상이며 가입 시 명시적으로 선택한 계정에만 생성한다.
- 사용자가 공식 OTA 계약이 없다고 확인했다. Airbnb·Booking.com·Trip.com·Expedia·Agoda의 계정별 숙소 식별 정보 설정만 제공한다. 실제 연결이나 동기화로 표시하지 않는다.
- 메시지는 초안 저장만 가능하며 외부 전송·보상 접수·예약 수집은 수행하지 않는다.

## 검증

- 기능 전환 및 인증 구현 후 `npm test`: 3개 테스트 모음, 64개 테스트 통과.
- 기능 전환 및 인증 구현 후 `npm run lint`, `npm run build`: 통과.
- 최종 EH 명칭 변경 후 `npm run lint` 재실행: 웹·API 타입 검사 통과. `git diff --check`도 통과했다. 명칭 변경 후 테스트와 빌드는 재실행하지 않았다.
- 예시 로컬 DATABASE_URL을 지정한 `npx --no-install prisma validate`: 통과. 데이터베이스 마이그레이션은 실행하지 않았다.
- 브라우저에서 모바일 로그인 레이아웃, 잘못된 비밀번호 차단, 정상 로그인, OTA ID 저장 후 새로고침 유지, 로그아웃을 확인했다.
- 브라우저 검증 계정은 `/tmp/project-eh-browser-qa`의 격리 저장소에만 생성했다. 검증 후 기본 저장소로 개발 서버를 다시 실행했다.

## 실행 및 후속 범위

- 로컬 웹 `http://localhost:3000`, API `http://127.0.0.1:4000`으로 실행한다. 외부 배포는 하지 않았다.
- 현재 저장소는 단일 API 프로세스용 JSON 파일이다. Prisma 관계형 모델은 준비했으나 API에 연결하지 않았다.
- 공식 OTA 계약 이후 인증 어댑터·객실 매핑·웹훅·동기화·메시지 송수신을 추가해야 한다.
- 외부 운영 배포 전 데이터베이스·백업·HTTPS·계정 복구 및 운영 정책 적용이 필요하다.

## 서비스명 확정

- 후속 요청에 따라 사용자에게 표시되는 서비스명을 **EH**로 통일했다. 로그인·콘솔 로고·페이지 제목·푸터·API 문서와 현재 안내 문서를 수정했다.
- 기존 계정 데이터 경로와 npm 워크스페이스 식별자는 유지해 저장된 데이터와 실행 명령의 호환성을 보존했다.
