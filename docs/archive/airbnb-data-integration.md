# Airbnb 주변 숙소 데이터 연동 가이드

확인일: 2026-10-16. 아래 내용은 공급자 선정과 구현 가이드이며 실제 API 연동은 완료되지 않았다.

## 목표와 후보

기준 Airbnb 숙소 `856170695951051858` 주변 반경 500m의 Airbnb 등록 숙소를 대상으로 동일 날짜·인원·유사 객실·취소 조건의 필수 비용 포함 숙박 총액을 비교한다.

우선 검토 후보는 **AirDNA Enterprise API**다. 공식 문서에 반경 비교 숙소 검색과 숙소별 미래 일별 가격 기능이 있다. API 키는 영업 문의로 발급받고 Bearer 인증을 사용한다. 관련 문서: <https://docs.airdna.co/>.

공개 기능 설명만으로 서울 종로의 데이터 제공, 정확한 예약 총액 제공, 이용 권한이 보장되지는 않는다. AirDNA를 Airbnb 공식 API 또는 공식 인증 파트너로 간주하지 않는다. 웹 대시보드 구독에 API 권한이 포함된다고 가정하지 않는다.

PriceLabs는 가격 운영 도구 후보로 검토할 수 있다. 다만 Customer API가 주변 Airbnb 숙소 각각의 원시 가격 데이터를 외부 앱에 제공하는지는 별도로 확인해야 한다. 문서: <https://developers.pricelabs.co/overview>, <https://help.pricelabs.co/portal/en/kb/articles/pricelabs-api>.

## 1. 결제 전에 샘플과 이용 조건 확인

공급자 홈페이지의 영업 문의 창구에 다음을 요청한다. 이 문서는 문의를 발송하지 않는다.

> 한국 서울 종로구의 숙소 운영을 위한 내부 가격 비교 앱을 개발 중입니다.
> 기준 Airbnb 숙소는 https://www.airbnb.com/rooms/856170695951051858 입니다.
> 해당 숙소 주변 반경 500m의 Airbnb 등록 숙소 목록과 숙소별 미래 날짜 가격을 API로 제공할 수 있나요?
> 예시 조건은 2026-11-11 체크인, 2026-11-12 체크아웃, 성인 1명, KRW입니다.
> 아래 내용을 확인할 수 있는 샘플 응답과 견적을 부탁드립니다.
>
> - 해당 기준 숙소 및 종로 지역 데이터 보유 여부
> - Airbnb 등록 ID·원문 링크·좌표 및 좌표 정확도, 반경 검색 지원
> - 객실 유형·정원·전용 욕실·엘리베이터 등 비교 조건 제공 범위
> - 일별 가격이 관측 판매가인지 추정치인지, 조회·갱신 시각
> - 날짜·인원별 실제 예약 가능 여부와 최소 숙박일 확인 가능 여부
> - 청소비·서비스 수수료·세금·할인·취소 조건을 반영한 숙박 총액 제공 여부
> - 경쟁 가격 분석·추천 가격 계산·외부 앱 표시·저장·캐시가 허용되는 계약 범위
> - API 권한이 포함되는 상품명, 최소 월 비용·초기 비용·호출 한도·초과 요금
> - 한국어 상담 가능 여부와 테스트 키 제공 여부

## 2. 샘플로 도입 여부 결정

- 기준 숙소가 없거나 종로 지역 표본이 부족하면 계약 전에 다른 공급자를 검토한다.
- 좌표가 근사값이면 반경 500m도 근사 거리로 표시한다. 정확한 반경을 보장하지 않는다.
- 일별 요금만 있고 수수료 등이 빠져 있으면 '1박 참고 요금'으로 표시한다. 실제 예약 총액으로 표시하거나 총액과 섞어 비교하지 않는다.
- 예약 가능 여부나 객실 조건을 확인할 수 없는 숙소는 검증되지 않은 후보로 남긴다.
- 추정값은 추정값으로 표시한다. 달력 차단을 실제 예약으로 단정하지 않는다.
- 샘플 확인과 데이터 이용 범위에 대한 서면 확인 후 API 상품을 계약한다. 현재 API 비용은 견적 확인이 필요하다.

## 3. Travel Watch 구현 순서

아래는 구현 예정 구조다. 엔드포인트나 환경변수를 추가한 상태가 아니다.

1. `apps/api`에 공급자 어댑터를 추가한다. 공급자 API 키는 서버에서만 읽고 `NEXT_PUBLIC_` 변수에 넣지 않는다. 실제 환경변수 이름과 로딩 경로는 어댑터 구현 시 `.env.example`에 문서화한다.
2. 공급자 문서와 발급 권한을 확인하여 반경 검색 → Airbnb ID가 있는 숙소 선택 → 내 숙소 제외 → 거리·객실 조건 검증 → 날짜별 가격 조회를 연결한다. Google Places 장소를 Airbnb 숙소로 대체하지 않는다.
3. 요청 날짜·인원·반경을 서버에서 검증하고 외부 응답의 ID·통화·금액·조회 시각·가격 의미·좌표 정확도를 검증한다. 페이지가 나뉘면 계약 호출 한도 내에서 처리한다.
4. 비교 가능한 총액이 확보된 숙소만 중간 가격 계산에 사용한다. 표본 부족·오류·오래된 가격·예약 불가·미조회는 구분한다. 최소 표본 및 가격 유효기간은 공급자 갱신 주기에 맞춰 정한다.
5. 추천 총액은 정책상 `max(최소 판매 총액, 비교 총액 중간값 × (1 - 할인율))`로 계산할 수 있다. 최소 판매 총액으로 인해 주변보다 비싸질 수 있음을 표시한다. 유효 데이터가 없으면 계산하지 않는다.
6. 개별 숙소·가격 스냅샷 저장 모델을 설계한다. 기존 `MarketRateSnapshot`은 지역별 집계 모델이므로 원문 조건·개별 출처를 충분히 보관할 수 있는지 확인한다. 계약에서 허용한 보존 기간과 필드만 저장한다.
7. `CollectionQueueService.collect()`는 현재 공급자 미설정 오류를 반환하는 상태다. 계약에서 허용한 갱신 주기·호출 제한·재시도 정책으로 실제 수집을 구현한다.
8. 프론트에서 숙소명·Airbnb 링크·거리 정확도·숙박 조건·가격 기준·조회 시각·유효 표본 수·추천가를 표시한다. 가격 변경은 사용자 확인을 거치는 수동 적용으로 시작한다.
9. 성공 응답, 범위 밖·내 숙소 제외, 조건 불일치, 오래된 가격, 표본 부족, 인증 실패, 호출 제한 및 큐 미연결 동작을 검증한다.

## 현재 상태

Google 지도·일반 숙소 검색은 동작한다. Airbnb 목록·가격 공급자 계약, API 키, 샘플 응답은 확보되지 않았다. 다음 단계는 공급자에 위 조건의 샘플과 API 견적을 요청하는 것이다.

Airbnb 자체 API는 가격 분석 목적의 권한을 별도로 확인해야 한다. 일반 호스트 관리 API 접근을 경쟁 숙소 데이터 이용 허가로 간주하지 않는다. [공식 API 약관](https://www.airbnb.com/help/article/3418).
